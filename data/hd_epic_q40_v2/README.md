# hd_epic_q40_v2 概覽

`hd_epic_q40_v1` 的去重版。每支影片取「最短且剛好包住 32 題互不重複題目的連續窗口」，窗口上限 15 分鐘。

- 報告數：62（15 分鐘內湊不到 32 題不重複題目的影片已排除）
- 總題數：1984（每份剛好 32 題，全部為 `single_choice`，5 個選項）
- 窗口長度：中位數 9.5 分鐘，範圍 3.4–14.8 分鐘
- 題型：定位 1677、how 166、why 124、weight 17
- 影片：尚未下載；題目只用標註 JSON 產生。

## 為什麼要去重

v1 同一份報告裡有互相洩漏答案的題目：

- 244 對定位題問同一個動作、標準答案是同一個時間區間（例如 `hdepic-dense-046` 的 `loc_6239` 與 `loc_4267`，都問 <put carrot>，答案都是 04:07）。470 題（定位題的 16%）牽涉其中。
- 41 題 how／why 題附上的片段就是某題定位題的答案（例如 `hdepic-dense-001` 的 `why_81` 片段 0:00:53.704–0:00:54.584，正是 `loc_7232` <place pan> 的正確選項）。

## 取樣方式

1–3、7 同 v1：同樣 4 個類別、只收帶 `start_time`/`end_time` 的單影片題目、排除選項重複的題目、時間改為相對片段起點。

4. **去重規則**（每份報告內，所有題型一起套用）：
   - **一個動作只出一題**：定位、how、why 題的動作標籤（`<...>` 內文字，小寫，`put down`／`leave` 視為 `put`）在一份報告裡只出現一次。同一動作的 how 和 why 也不並存。
   - **證據區間不重疊**：定位題的證據是正確答案的時間區間；how／why／weight 的證據是題目片段。任兩題的證據區間不重疊。
5. **找窗口**：以每題的起點為候選窗口起點，把起點之後的題目依結束時間排序，逐題加入、跳過違反去重規則的題目，加到第 32 題時的結束時間就是窗口終點。取最短的窗口。
6. 窗口超過 900 秒的影片排除。
7. 每份報告**剛好 32 題**（v1 會把窗口內多出的題目也收進來，v2 不收），題目依來源順序排列。
8. 產生方式（原始標注來自 https://github.com/hd-epic/hd-epic-annotations 的 `vqa-benchmark/`）：
   `python scripts/build_hd_epic_dense.py <vqa-benchmark 目錄> data/hd_epic_q40_v2 --videos 1000 --target-q 32 --max-window 900 --max-q 100 --dedup`

去重是貪婪的（依結束時間先到先收），不保證是題目最多或窗口最短的組合；同樣的參數重跑會得到同樣的結果。

## 已知限制

- 題型仍然很偏：定位題占 85%，無法平均混合。
- 去重只看動作標籤與時間區間，不保證題目語意上互相獨立（例如不同動作標籤描述同一件事）。
- 報告 ID 從 `hdepic-dense-001` 重新編號，跟 v1 的同名 ID 不是同一支影片或同一個窗口。
- 參與者分布不平均：P01 11 份、P03 12 份，P06、P07 各 2 份。
