# cc4d 題數 × 題型組成測試方法（草稿）

## 目標

模型固定，只改變一份報告的**題目數量**和**各題型的比例**，看 VLM 回答同一支影片的
表現怎麼變。設計方式參考 `data/hd_epic_loc_nested_v1`：影片和題目不變，只換子集合和
順序。

## 固定條件

- 模型、生成參數（temperature 0）、prompt 模板。
- 影片輸入：同一個 `time_range`，以及相同的 fps 和解析度。
- context：`task_name`、`recipe`、`error_definitions`。
- 題目文字、選項和答案都沿用 `cc4d_dense_v1`，不修改。

## 為什麼只測三種題型

CC4D 的步驟標注只有兩種資訊：時間（`start_time`、`end_time`）和錯誤（`errors`）。
`correct`（bool）、`error_types`（multi_choice）、`duration`（seconds）已經把它們用完了。
要讓每個步驟再多一題 `single_choice` 或 `int`，只剩兩種來源，兩種都不適合：

- **順序**，例如「X 之前緊接著做的是哪一步」、「X 是第幾個做的步驟」。這類題目會被
  context 裡的 `recipe` 洩漏。依 task graph 計算，358 個食譜步驟中有 130 個（36%）的
  名次完全由食譜決定，其餘步驟的可能名次中位數只有 2 個。做得正確的影片，看食譜文字
  就能答。
- **時長**：跟 `duration` 重複。


**如果要測五種題型**：讓三種格式問同一個時長。

| 題型 | 題目 | 答案 |
| --- | --- | --- |
| `seconds` | 步驟「X」花了幾秒？ | `end_time − start_time` |
| `single_choice` | 步驟「X」花了多久？（8 個時間區間） | 時長所在的區間 |
| `int` | 步驟「X」花了幾秒？（回答整數） | 時長四捨五入 |

- 同一步驟只能出其中一種，否則答案會互相洩漏。
- 時間區間的切點用 `cc4d_dense_v1` 步驟時長的八分位數，讓 8 個區間的答案數量大致相同。
- `int` 用精確比對。四捨五入後的誤差容許度，比 `seconds` 的 max(2 s, 25%) 嚴格很多。
  比較兩者時，要記得這是評分規則造成的差異，不是格式本身的差異。
- 好處：三種格式問的是同一種內容，測到的是純粹的格式效果。相對地，目前 bool、
  multi_choice、seconds 各自問不同內容，題型效果和內容難度分不開。

## 實驗條件（每支影片 10 種）

| 題數 | 只有 bool | 只有 multi_choice | 只有 seconds | 混合（各 1/3） |
| --- | --- | --- | --- | --- |
| 6 | ✓ | ✓ | ✓ | ✓ 2/2/2 |
| 12 | ✓ | ✓ | ✓ | ✓ 4/4/4 |
| 24 | | | | ✓ 8/8/8 |
| 48 | | | | ✓ 16/16/16 |

- **巢狀**：小集合包含在大集合內，同一題可以跨條件配對比較。
- **混合題型的步驟分配**：16 題以下時，每個步驟只問一種題型，因為同一步驟的
  `correct` 和 `error_types` 答案可以互相推出。24 題和 48 題無法避免一個步驟問到
  多種題型，這是這兩個條件本身的限制。
- **順序**：每個條件 3 種順序。把 48 題打亂一次，依三等分輪轉，再篩出各條件的子集合。
- **沒有逐題 baseline**：每題單獨問的成本太高（每次都要送整支影片）。改以 6 題作為
  干擾最低的一端，所以結果沒有「1 題」這個點。

## 呼叫次數

10 個條件 × 3 種順序 = **30 次**每份報告/影片的呼叫，不含重試。

## 分析

1. **題數效果**：混合題型 6 → 12 → 24 → 48 的準確率，分整體和分題型。
2. **題型效果**：同樣是 6 題或 12 題時，比較同一題在「單一題型」和「混合」條件下的
   對錯，使用配對比較（McNemar，或以影片和題目為隨機效應的 logistic 模型）。
3. **位置效果**：題目在 prompt 中位於前、中、後三段時的準確率。
4. 每項結果都附上**多數答案基準線**，以及格式失敗數（`missing_answer`、
   `invalid_answer`、`invalid_output`）。

評分規則依 `docs/scoring_rules.md`。
