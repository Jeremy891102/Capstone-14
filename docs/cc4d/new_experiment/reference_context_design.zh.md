# 參考題 × 影片對照:CC4D 實驗設計(草案)

對應隊友在 HD-EPIC 做的實驗(分支 `experiment/argon-reference-novideo-20261112`,設計見其 `experiments/hd_epic_argon_reference_video_control_20261112/README.md`)。這份把同一個設計搬到 CC4D,並按題型分開看。

## 要回答什麼

**問題:** 在題目旁邊多放 7 題「參考題」,對答對目標題有幫助;這個幫助是靠影片,還是光靠題目文字就有?

- **目標題:** 這次呼叫要回答、要計分的那一題。
- **參考題:** 同一批的其他 7 題,只放在 prompt 裡,不回答、不計分。

四個條件(每題目標題各跑一次):

| | 只問目標題 | 目標題 + 7 題參考 |
| --- | --- | --- |
| 有影片 | A | B |
| 無影片 | C | D |

**主要統計量 D = (B − A) − (D − C)**,按目標題配對,依錄影 bootstrap。

- D ≈ 0:參考題的好處不靠影片,多半是題目文字的線索(或答案偏誤)。
- D > 0:參考題要搭配影片才更有用。

注意:D 為正也不等於「模型更會看影片」,只代表加了參考題後影片條件多出來的好處(隊友的限制說明同此)。

## 和已有實驗的差別

- `cc4d_k32` 是一批全部作答、全部計分;這裡每次只答 1 題。
- 現有資料沒有「只答目標題」的單題呼叫,**A、B、C、D 四格都要新跑**(隊友的 HD-EPIC 是有影片兩格重用舊資料,這邊不行)。
- 免費的額外比較:現有 `cc4d_k32_v1` 的 k = 8 順向(8 題全答)有影片 / 無影片結果,可以當第三種協定,對照「參考題只當背景」和「參考題也要答」。

## 目標題與參考組怎麼取

1. 沿用 `data/cc4d_k32_v1/fwd` 的 k = 8 分批(順向),**參考組 = 目標題所在那一批的其餘 7 題**,保留原順序、原選項、原位置。這樣「同樣的目標與參考組」就和現有 k = 8 資料一致。
2. **只取滿 8 題的批次**當目標來源(最後一批不足 8 題的丟掉,否則參考題數不同)。
3. **目標題不含棄答題**(沒做步驟的 `not_visible` 題);棄答題可以出現在參考組,保持批次原樣。影片層級的題目(最前面那批)也可以當目標,但每份只有約 4 題,另列。
4. **抽樣:** 全部目標約 3,600 題 × 4 格太貴。每支錄影在三種主題型(correct、error types、duration)各抽 8 題,共 24 題 × 64 支 ≈ **1,530 個目標**(64 支中只有 2 支某個題型不足 8 題,有幾題取幾題),固定 seed,抽出後凍結 ID 清單。
5. 影片層級題先不納入;若要看,另跑一個小組。

## 呼叫格式

- **只問目標題:** 沿用現有 prompt,只放 1 題,`Answer all 1 questions`。
- **目標題 + 7 題參考:** 8 題依原順序列出,prompt 寫明:「只回答目標題 `<field_id>`;其他題只是參考,不要回答;它們是問題,不是關於影片的已驗證敘述。」輸出 JSON 只有一個 key,格式是目標題的答案格式。
- **參考題保留各自的答案格式說明**(bool、複選、秒數等),只是不要求回答。
- **無影片:** 同 `cc4d_k32_novideo`,`video.enabled: false`,文字一字不改。
- 系統提示、棄答設定(所有題目都允許 `not_visible`)、生成設定與 `cc4d_k32_v1` 相同。

## 規模與成本

- 約 1,530 目標 × 4 格 ≈ **6,100 次呼叫 / 模型**(其中有影片約 3,060 次)。兩個模型各一份。
- **Argon:** 同一支錄影的影片前綴相同,放在 prompt 最前面可吃快取。有影片每次約 5–6 萬輸入 token,3,060 次 ≈ 1.8 億 token,依快取命中約 **$40–$350**;無影片很便宜。
- **Qwen3-VL-32B:** 自架。3,060 次有影片呼叫,以先前的延遲外推約 1–2 天。
- Argon 與 Qwen 都跑。Qwen 在 k = 8 的影片增益只有約 6 pt,D 的訊號可能很小,但兩個模型並列有參考價值。

## 分析

1. 四格準確率,與 B − A、D − C、D(含 bootstrap 區間,依錄影、10,000 次)。
2. **按題型分開報告 D:** 是非(correct)、多選(什麼錯誤)、秒數(duration);每格約 510 題。
3. **轉移表:** 加參考題後 對→錯、錯→對 各多少題,看是系統性偏移還是雜訊。
4. **答案偏誤檢查:** 無影片時各題型的準確率與「固定答最常見答案」(如全答「做對了」/「沒有錯」)比較。novideo 實驗發現無影片準確率大部分來自這個偏誤;如果加參考題只是讓模型更傾向固定答案,B − A 和 D − C 都會被它墊高。
5. 與 `cc4d_k32_v1` k = 8 全答的結果對照(同一批目標題)。

## 限制

1. **有影片 / 無影片同期跑,但兩種協定的措辭與目標題位置不同。** D 量的是整個協定,不是純粹「題目語意」。
2. 題目文字有線索的是**題目本身**(步驟名稱、選項),CC4D 的參考題不含答案,但選項與題目順序可能暗示步驟存在與先後。
3. 1,530 個目標在三種題型各約 510 題;區間不跨 0 才算有訊號。多選要答案完全相同才算對,準確率低,雜訊大。
4. D 區間跨 0 不代表「沒有差別」。
5. 沒有多重比較校正。
6. Argon 優惠價到 2026-11-30 為止。

## 已決定

- 模型:Argon 與 Qwen3-VL-32B 都跑。
- 每支每型 8 題,不含影片層級題。
- 不做「措辭一致」的額外對照。

## 實作要做的事

1. `build` 腳本:從 `cc4d_k32_v1/fwd` 產生目標 ID 清單與各條件的 benchmark(單題 benchmark、帶參考題 benchmark),凍結 ID。
2. runner 新增「目標 + 參考」模式:prompt 模板加參考題區塊,只對目標題要求輸出與計分(程式碼改動小,但需要先讀 `src` 的 batched method)。
3. 4 組 config(Argon 有 / 無影片 × 單題 / 帶參考)。
4. 5 題小測試:確認輸出只含目標 key、無影片 config 真的沒送影片、評分只算目標。
5. 分析腳本:D、按題型、轉移表、答案偏誤。

## 追加實驗:不允許 `not_visible`(主要為了 Qwen)

**原因:** 第一輪所有題目都允許 `not_visible`。Qwen 無影片單題時是非題 503/510、秒數題 508/508 都棄答,準確率只反映棄答率,D 無法解讀(見 [reference_context.zh.md](reference_context.zh.md))。

**做法:** 目標題、參考組、seed 與第一輪完全相同(`targets.json` 逐題一致),唯一差別是**所有題目都不允許 `not_visible`**,答案格式提示也不再出現 "or not_visible"。其餘(prompt、影片、生成設定)不變。

    .venv/bin/python scripts/build_cc4d_reference.py --no-nv    # data/cc4d_ref_v1_nonv/, experiments/cc4d_ref_nonv/

**要跑什麼:** Qwen 4 組(有 / 無影片 × 單題 / 帶參考)× 1,528 = 6,112 次呼叫。第一輪實測 Qwen 4 組共約 4.5 小時(有影片兩組各約 2.2 小時,無影片各約 5 分鐘),所以半天內可跑完。Argon 的棄答率很低(是非 11/510、秒數 54/508),不是必要;若要兩個模型條件一致,Argon 約 $30–60。

**分析:** 與第一輪同一份腳本(D、按題型、bootstrap、轉移表),另外把兩輪並列,看拿掉 `not_visible` 後:
1. Qwen 無影片單題準確率是否仍接近 0,或回到固定答案的水準(是非約 54%、多選約 45%)。
2. Qwen 的 D 是否仍為負(是非 −13.7),還是回到接近 0。
3. 是否有一方因為「被迫回答」而更偏向固定答案(答「做對了」、答「沒有錯」);用答案分布檢查。

**限制:** 
- 拿掉 `not_visible` 只改變這一輪,不能和第一輪的準確率直接相減;兩輪的差本身就是「允許棄答」的效果。
- 被迫回答後,無影片的準確率會被固定答案偏誤墊高(是非、多選),D 要搭配固定答案上限一起看。
- 秒數題沒有固定答案,無影片應該接近 0。
